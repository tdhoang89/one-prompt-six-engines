How the experiment works

Which web game technique does an AI handle best — fastest, smoothest, best looking? To compare fairly, everything is held fixed except the engine.

  1. Same prompt

    Written once, kept word for word for every build.

  2. One variable

    Only the KỸ THUẬT (technique) line changes.

  3. Same model

    Claude Opus 5.5 at High effort, in Claude web chat — a fresh chat for each engine.

  4. One HTML file

    No outside images, sounds or fonts. Everything is drawn in code; sound comes from the Web Audio API.

What Neon Swarm tests

An arcade game for adults, played with one finger. Dodge a swarm of glowing shapes, collect 10 energy orbs to fire a shockwave, and set off chain reactions for combos. Close calls earn a bonus, and every 15 seconds the swarm gets bigger and faster.

  • Hundreds of objects on screen at once
  • Glow made with the engine's strongest tool: bloom, filters or shaders
  • 3D builds: explosions light up the objects around them
  • Screen shake and a moment of slow motion on big chain reactions
  • An always-on counter for FPS and objects on screen
  • Stress test: you can't lose, enemies keep coming until average FPS stays under 50 for 3 seconds

Details

The six techniques, how builds are scored, and what to keep in mind when reading the results.

The six techniques
Technique Version Type Library (min, not gzipped) Packing into one HTML file

How builds are scored

  • Works on first try — yes / no
  • Fix rounds — how many times the AI had to be asked to fix it
  • Average FPS in normal play, on a real phone
  • Rotate / fold — does the layout break?
  • Own lines of code and file size — measured by script
  • Stress test — max objects while FPS stays ≥ 50
  • Built-in vs hand-made effects — from the AI's report
  • Look & feel — scored from 1 to 5

Hypotheses not verified yet

  • PixiJS and Phaser reach the highest object counts among the 2D builds in the stress test.
  • Plain HTML5 Canvas runs out of breath first if its glow is done with shadowBlur.
  • three.js, Babylon.js and PlayCanvas have the best lighting, but heavier files.

Reading the results

  • The stress test only means something on a real device (for example a Galaxy Z Fold 8). Headless browsers have no real GPU, so their numbers don't count.
  • These builds were made in Claude chat and load their engine from a CDN, so they need internet. Builds made with Claude Code embed the engine and run offline.
  • Results depend on the model and the date — every build records both.
  • Screenshots show about 3 seconds of automated play on a laptop, so the FPS in them is not a result.

Left out on purpose

  • Godot — its web export is several files, including a .wasm tens of MB in size, and needs a server, so it can't be one HTML file. Godot suits native APK exports better.
  • PlayCanvas Editor — a web editor whose projects export as a folder; an AI would need MCP to drive it.
  • Unity — depends on the editor and prefabs, and is heavy; not a good fit for an AI to build on its own.
